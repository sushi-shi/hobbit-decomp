# hobbit-decomp

C++ reconstruction of **The Hobbit (2003)**, PC no-CD v1.3 (`Meridian.exe`),
built with the pinned Visual C++ 6.0 toolchain under Wine. Retail bytes decide
correctness; hashes are in [config/retail/targets.json](config/retail/targets.json).
Tooling and source ownership follow local Gruntz and HoMM1. Xbox symbols and
sibling Entropy source provide evidence, checked against the PC executable.
Supply your own matching executable and game data. Original binaries, maps,
media payloads and their download links are excluded from this repository.
Full input hashes are in `config/retail/targets.json`.

## Quickstart

With Nix flakes enabled, install the pinned SP5 header from your compiler media,
then enter the matching shell from the repository root. The installer requires
`7z` and `cabextract`; it verifies the media and header hashes in
`nix/toolchain-identities.json`.

```sh
python3 scripts/toolchain/install_sp5_xtree.py --media /path/to/VS6sp5.exe
HOBBIT_SKIP_INIT=1 bin/hobbit-shell
hobbit init --exe /path/to/Meridian.exe
hobbit inspect
hobbit build
hobbit match x_files_x_plus
hobbit verify status
hobbit sema disasm 0x247b00
```

Initialization verifies and stages your input in ignored `build/orig/`;
omit `--exe` on subsequent runs. `bin/hobbit-shell --command hobbit build`
runs a single command. The shell stages the private SP5 header from ignored
`build/toolchain/vc6-sp5/`. Compiler binaries, extracted media, Wine state,
analysis and comparison artifacts stay in ignored `build/`.
Matching does not require Ghidra. For the optional Ghidra viewer, use
`bin/hobbit-shell --viewer` and `hobbit ghidra build`.

## Improve a function

Choose an annotated function in an imported engine unit, inspect the PC bytes,
edit the C++, and rebuild its unit:

```sh
hobbit sema disasm 0x247b00
hobbit match x_files_x_plus
hobbit verify status
hobbit verify readme
```

`hobbit verify bank` records CUR, MAX and HIST. `hobbit verify readme`
regenerates the score tables from the current comparison report without changing the ledger.

## Matching work

Import available genuine engine source first, then repair revision differences
and polish matches. Start with annotated functions in Animation, UI, Draw,
Resource Manager, Audio, I/O or collision units from `config/units.toml`.
Unannotated bodies need independently supported PC identities. Recover real
shared layouts and APIs; keep every relocation in the comparison.

Source code, RVA/DATA annotations and config are the reconstruction record.
Disassembly, generated claims, comparisons and diagnostics stay in ignored
`build/`. Do not commit assembly, notes, proof packages or duplicate snapshots.
See [AGENTS.md](AGENTS.md) for contributor instructions and
[editor setup](editor/nvim/README.md) for integration.
